## Запуск и сборка

Нужны JDK 25, Maven и установленный родительский `ru.pukpukov:puklapom:1.4.10`
(исходники: `../../lib/puklapom`). Конфигурация JVM для его Checker Framework
включена в `.mvn/`.

```sh
mvn javafx:run
mvn verify -Drelease=false -Dtests.skip=false  # быстрый цикл с тестами
mvn clean package -Dtests.skip=true           # полная компиляция с Checker Framework
java -ea -jar target/territory-war-1.4.jar
```

`clean` при переходе от быстрой сборки к полной нужен, чтобы javac с чекерами
не использовал уже готовые классы Takari. Основной JAR содержит точку входа и зависимости; упаковка целиком наследуется
от puklapom, без локального переопределения поведения shade.
Компиляция алгоритмов — в памяти через [jOOR](https://github.com/jOOQ/jOOR).

## Симуляции и поиск победы

- **Число игр** задаёт размер пакетной симуляции: по умолчанию 10000, можно ввести
  любое целое число от 1 до 2147483647. **Симулировать** запускает пакет параллельно.
- Выберите **Бот 1** или **Бот 2** и нажмите **Искать победу**. Поиск перебирает игры
  до первой строгой победы выбранного бота; ничья не подходит. Лимита числа попыток
  нет, кнопка **Отмена** и закрытие окна останавливают поиск между ходами.
  Если бот никогда не побеждает, поиск нужно отменить.
- **Смотреть запись** воспроизводит последнюю найденную победу с начала. Работают
  скорость и пауза; повторное нажатие начинает запись заново. Запись не зависит
  от последующих правок алгоритмов. **Сброс** возвращает обычный режим, но запись
  не стирает. Неудачная/отменённая новая попытка поиска также не стирает её.
- Записи создаются **только во время поиска**. Обычная игра, пакетные симуляции и
  просмотр ничего не записывают. Сохраняются порядок первого хода и реальные
  направления/пропуски ходов; воспроизведение использует тот же движок и правила,
  а не повторно запускает случайный алгоритм. Записи неподходящих игр не хранятся.
- Запись хранится **в памяти до закрытия приложения**, экспорта на диск пока нет.
  Код ботов выполняется без песочницы: зависший внутри `move()` алгоритм нельзя
  принудительно безопасно прервать, отмена проверяется между вызовами.

Правила сохранены: замкнутые области заполняются один раз **в конце** игры.
Исключение выполнения бота означает пропуск хода с сообщением в логе; ошибки
инвариантов и VM не маскируются под пропуски. Ошибка создания бота прерывает
симуляцию и показывается, а не исчезает из итоговой статистики.

## Проверки

Тесты фиксируют поведение исходного движка, порядок ходов, точность каждого тика
записи, отсутствие записи вне поиска, число игр, отмену и диагностику компилятора.
Для интеграционного теста JavaFX нужен графический сеанс:

```sh
mvn test -Drelease=false -Dtests.skip=false -Dui.test=true
```

UI проверяется дочерним процессом во временной папке: пользовательские `bot1.java`
и `bot2.java` не изменяются.

Синхронизация кода с диском сохраняет локальную версию в соседний
`*.conflict-*.java` и уведомляет при обнаружении одновременных правок; затем
загружается версия с диска. Сохранение атомарное: если файловая система не
поддерживает `ATOMIC_MOVE`, показывается ошибка вместо тихого неатомарного обхода.

Проверка основного JAR после сборки:

```sh
mvn test -Drelease=false -Dtests.skip=false -Dtest=JarPackagingTest -Dpackaged.jar=target/territory-war-1.4.jar
```
